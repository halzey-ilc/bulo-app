# Обмен BULO ↔ 1С

Документ для программиста 1С («Ярос Групп»). Обмен работает в двух режимах — можно использовать оба одновременно.

| Режим | Как работает | Когда подходит |
|---|---|---|
| **Автоматический** | 1С по расписанию сама обращается к API BULO: отправляет справочники и забирает документы | Основной режим после настройки |
| **Excel** | Бухгалтер выгружает документы в Excel в веб-панели (раздел «1С») и загружает их в 1С | Пока автообмен не настроен, или как запасной вариант |

Инициатор обмена всегда 1С, поэтому базе 1С не нужен внешний адрес — достаточно доступа в интернет.

## Подключение

- Адрес: `https://<домен-bulo>/api/onec/...`
- Авторизация: заголовок `X-Api-Key: <ключ>` (ключ задаётся в переменной `ONEC_API_KEY` на сервере BULO).
- Формат: JSON, UTF-8. Даты — `ГГГГ-ММ-ДД`, суммы — числа с точкой.
- Ответ при ошибке: HTTP 4xx/5xx и `{"message": "..."}`.

## 1С → BULO: справочники

Рекомендуемое расписание: номенклатура и цены — каждый час, контрагенты — раз в сутки. Повторная отправка безопасна: записи сопоставляются по коду 1С (`id`) и обновляются.

### Номенклатура и группы

`POST /api/onec/import/nomenclature`

```json
{
  "groups": [{ "id": "00-000001", "name": "Синнабоны" }],
  "items": [
    {
      "id": "00-000123",
      "name": "Синнабон классический",
      "groupId": "00-000001",
      "unit": "шт",
      "multiplicity": 6,
      "description": "необязательно",
      "weight": "120 г",
      "shelfLife": "48 часов"
    }
  ]
}
```

Группы становятся категориями каталога. Фото, описание и видимость товара в приложении ведутся в BULO — 1С их не перезаписывает (описание берётся из 1С, только если в BULO его нет).

### Типы цен

`POST /api/onec/import/price-types`

```json
{ "items": [{ "id": "000000001", "name": "Оптовая", "isDefault": false }] }
```

Тип с `isDefault: true` применяется к партнёрам без индивидуального типа цен.

### Цены

`POST /api/onec/import/prices`

```json
{ "items": [{ "productId": "00-000123", "priceTypeId": "000000001", "price": 162.0 }] }
```

`productId` и `priceTypeId` — коды 1С. Строки с неизвестными кодами пропускаются и возвращаются в поле `skipped`.

### Контрагенты

`POST /api/onec/import/counterparties`

```json
{ "items": [{ "id": "00-000045", "name": "ИП Асанова", "inn": "01234567890123", "address": "...", "phone": "..." }] }
```

Контрагенты не создают партнёров автоматически: администратор в веб-панели сопоставляет новую лавку с контрагентом 1С (поиск по названию или ИНН).

## BULO → 1С: документы

BULO ставит документы в очередь в момент события:

| `type` | Документ 1С | Когда создаётся |
|---|---|---|
| `CUSTOMER_ORDER` | Заказ клиента | Менеджер одобрил заказ |
| `PRODUCTION` | Заказ на производство / Производство | Цех сформировал сводную накладную |
| `SALE` | Реализация товаров и услуг | Заказ передан курьеру (отгружен) |

### Забрать документы

`GET /api/onec/outbox?limit=50` — новые документы и документы с ошибкой (до 10 попыток), старые первыми.

```json
[
  {
    "id": "cmh...",
    "type": "CUSTOMER_ORDER",
    "createdAt": "2026-11-02T08:15:00.000Z",
    "attempts": 0,
    "payload": {
      "orderNumber": 15,
      "date": "2026-11-02T08:10:00.000Z",
      "deliveryDate": "2026-11-03",
      "shippedAt": null,
      "counterparty": { "oneCId": "00-000045", "name": "ИП Асанова", "inn": "01234567890123" },
      "priceType": "000000001",
      "deliveryAddress": "г. Бишкек, ул. Киевская, 95",
      "comment": null,
      "paid": false,
      "paymentMethod": null,
      "items": [
        { "productOneCId": "00-000123", "name": "Синнабон классический", "unit": "шт", "qty": 24, "price": 162, "sum": 3888 }
      ],
      "total": 3888
    }
  }
]
```

Для `PRODUCTION` поле `payload` такое:

```json
{
  "sheetNumber": 7,
  "date": "2026-11-03",
  "isSupplement": false,
  "items": [{ "productOneCId": "00-000123", "name": "Синнабон классический", "unit": "шт", "qty": 120 }]
}
```

`isSupplement: true` — дозаказ: заказы, оплаченные после формирования основной накладной на эту дату.

### Подтвердить документ

`POST /api/onec/outbox/{id}/ack`

```json
{ "ok": true, "number": "ЗК-000123" }
```

или при ошибке:

```json
{ "ok": false, "error": "Не найден контрагент 00-000045" }
```

Подтверждённый документ больше не выдаётся. Документ с ошибкой выдаётся повторно (до 10 попыток); ошибки видны бухгалтеру в веб-панели, оттуда же документ можно отправить заново.

## Excel-выгрузка

Веб-панель → «1С» → «Выгрузить в Excel». В файле два листа:

- «Заказы и реализации» — по строке на позицию: документ, № BULO, дата, код и название контрагента, ИНН, адрес, код номенклатуры, количество, цена, сумма;
- «Производство» — сводные накладные по позициям.

Галочка «отметить как выгруженные» помечает документы переданными, чтобы при автообмене они не задвоились.

## Тестирование

### Без 1С — симулятор

`scripts/onec-simulator.mjs` ведёт себя как база 1С: отправляет справочники и забирает документы через те же точки API.

```bash
node scripts/onec-simulator.mjs           # один цикл обмена
node scripts/onec-simulator.mjs --watch   # каждые 30 секунд, как регламентное задание
node scripts/onec-simulator.mjs --fail    # «1С» отклоняет документы — проверка журнала ошибок
```

Что проверить: в каталоге появился «Синнабон с фисташкой (из 1С)», в поиске контрагентов при одобрении партнёра — «ИП Садыкова», на странице «1С» веб-панели документы перешли в «Передан» с номерами вида `ЗК-000001`, а в режиме `--fail` — в «Ошибка» с текстом и кнопкой «Повторить».

### С тестовой базой «Ярос»

1. «Ярос» делает копию рабочей базы 1С (тестовую) и пишет обработку обмена по этой инструкции.
2. API BULO должен быть доступен из интернета: тестовый сервер или временный туннель (например, Cloudflare Tunnel) к локальному API.
3. Передаём «Ярос» адрес API и ключ `ONEC_API_KEY` (отдельный для теста).
4. Прогон:
   - 1С отправляет справочники → проверяем товары, цены и контрагентов в веб-панели;
   - в приложении партнёр делает заказ, менеджер одобряет → в 1С появляется «Заказ клиента»;
   - бухгалтер отмечает оплату, цех формирует сводную накладную → «Заказ на производство»;
   - курьер забирает заказ → «Реализация товаров и услуг»;
   - намеренная ошибка (например, контрагент без кода 1С) → документ в «Ошибка», после исправления — «Повторить».
5. Сверка: суммы и количества в документах 1С совпадают с накладными BULO; Excel-выгрузка того же периода совпадает с документами.

## Что нужно уточнить у «Ярос»

1. Конфигурация 1С (Бухгалтерия 3.0, УТ 11, УНФ или другая) и где она работает (своя база или облако).
2. Каким документом оформлять производство: «Заказ на производство» или сразу «Производство».
3. Нужна ли печатная форма накладной именно в формате 1С — пришлите образец, повторим в веб-панели.
